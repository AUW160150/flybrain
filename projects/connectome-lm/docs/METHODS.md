# Implementation methods

The immutable local [analysis plan](analysis_plan.md) states the hypotheses, budgets, seeds and interpretation rules. Its initial receipt predates training. No Git repository exists at the workspace root, so the recorded Git revision is null; a SHA-256 over Python sources, presets and project metadata identifies each implementation. No public preregistration is claimed.

## Extraction and controls

Curated inventory is `status == Traced`, excluding exact explicit non-neuronal/error labels in statusLabel/superclass/class/type. Missing type labels stay. All other statuses and unresolved classifications are reported. The pair table has only integer body_pre/body_post/weight fields. All raw ordered pairs are audited exactly with 32 temporary disk partitions before filtering; any duplicate aborts rather than guessing whether to sum. Both endpoints must be curated, anatomical count at least 5, self-edge removed. Compact directed CSR is used for component discovery. Weak connectivity is used only for sampling. Ties choose the component with the smallest original body ID. A seeded uniform start and reproducibly shuffled sorted neighbor lists define BFS; final edges are the induced directed graph and model indices follow sorted original IDs.

Rewiring implements the directed three-edge path move described in NetworkX's documentation, with an explicit loop-free guard and auditable counters. A start node is drawn proportional to its fixed total degree, then three outgoing partners are drawn uniformly. Dead ends and all rejected proposals count toward 500E; valid accepted three-edge swaps count toward 20E. The implementation permits three-cycle reversals. Every null starts from the real graph. Diagnostics at 0/E/5E/10E/20E include overlap, degrees, reciprocity and weak/strong components. Exact labelled degrees, simplicity, loop exclusion and partner changes are verified. Failure makes the control invalid and halts the matrix; no unchanged fallback, connectivity selection or performance rejection. A finite swap count does not establish mixing or uniformity. Random-density samples an E-subset uniformly from all N(N−1) directed loop-free pairs.

## Model and accounting

For embedding width d, N graph nodes and E directed edges, the main active parameter count is `512d + 2Nd + N + 256 + E`. Interfaces contribute `512d + 2Nd + 256`; recurrent bias contributes N; the edge vector contributes E. Buffers store source/target indices (16E bytes at int64). Dense execution differentiably assembles an N×N matrix, but it is not a parameter and has no N×N optimizer state. Scatter and sparse COO variants use the same edge vector; CPU float64 forward/backward tests compare each against an independent tiny dense reference.

Interfaces use local-seeded normal embeddings (std .1), Xavier-uniform input/readout/output matrices and zero biases. Every incoming target slot gets seeded standard-normal noise, row-normalized to .9. Fly and degree-rewired arms have identical row slot vectors and interface parameters; edges are sorted by target then source. Counts are ignored by primary initialization. Alpha .5 retention is an engineered self-memory rule. The diagonal ablation has N independently learned coefficients and the same interfaces; it is not parameter matched. Graph models contain no attention, cross-node normalization or embedding-to-logit bypass.

GRU width minimizes absolute active parameter-count mismatch over widths 1..2048, with executable <=5% acceptance. GRU count is `512d+256+3hd+3h²+6h+dh`. Transformer optional search uses 1..4 layers, d fixed, four attention heads, FF widths 4..2048 in multiples of four, learned positional embeddings, rank-d readout and no dropout. The selected architecture minimizes count mismatch, never validation loss. Every registered parameter participates in forward/backpropagation; there is no padding. GRU biases are zero; its recurrent weights otherwise use PyTorch defaults. Transformer internal weights use PyTorch defaults, with std .1 embeddings/positions, Xavier output/readout, zero output bias. Optional model compute differs.

## Text and training

Tiny Shakespeare bytes are unchanged. Contiguous offsets use exact integer floors of 90% and 95% before window creation. Rolling-hash candidate duplicate matches are verified byte-for-byte and extended to maximal shared spans; reports expose only offsets/lengths/digests. Fixed vocabulary includes all 256 byte values. Training window starts are uniform from the valid split range, hidden state zero per independent window. Data-order seed derives only from training seed, so all arms receive identical windows at equal update/batch/context budgets. Extraction, null topology, interfaces, row slots, data, runtime, run order, perturbations and generation use distinct named seed streams. Derivation is SHA256 of canonical JSON `[stream, integer keys...]`, first eight hex digits modulo 2³¹−1. Null keys are sampling seed/training seed/null index. Interface and row-slot keys use training seed and target index as appropriate.

Evaluation partitions L−1 prediction positions into consecutive context-sized blocks, independently zeroing state. Only padding in the final block is masked, so every target byte except the split's first is scored exactly once. All arms receive identical context boundaries. Evaluation accumulates natural-log per-position loss in float64, divides by scored bytes and ln(2) for BPB; byte perplexity is 2^BPB. Training/tuning use a development-only corpus API; the final test capability lives in a separate explicit command.

AdamW uses betas .9/.999, eps 1e−8, zero decay, no graph dropout, norm-1 clipping and float32 deterministic algorithms. Updates always consume the full preset. Best-validation and final checkpoints are stored independently. Atomic latest checkpoints save optimizer, Python/NumPy/Torch/accelerator RNGs, sampler position, metrics and elapsed training/validation meters. CPU resume equivalence is tested bit-for-bit for model/optimizer/window streams. Nonfinite values or backend exceptions produce persistent failure records and stop the matrix.

CPU thread count is fixed at two. Device checks perform forward/backward and compare predictions with CPU. Accelerator time is synchronized. Training time includes window assembly, forward/backward, clipping and optimizer update, and excludes validation/checkpoint/report time. Graph/model initialization, preprocessing and validation have separate timing fields. Compilation is unused and recorded as zero. RSS is the process-lifetime high-water and may include earlier runs; it is not a precise per-run tensor allocation measurement. CUDA peak allocation is available only for CUDA; no unsupported MPS peak is fabricated.

## Analysis and secondary studies

One fly run is paired with the mean of its independently rewired nulls for each training seed. Bootstrap resamples those paired seed effects 10,000 times, not bytes or repeated uses of one fly run. Replication resamples graphs and then within-graph paired training seeds while retaining every graph separately. Samples may overlap and come from one animal. Smoke makes no statistical claim; pilot is validation-only; five confirmation seeds give limited uncertainty. Conventional baselines, contact initialization, generated examples and artificial-model interventions remain secondary. Frozen-fly trains interfaces with fixed random core. Count initialization and target-row count shuffling use the same noise and normalize rows identically; learned signs remain unrestricted.

Fixed-time is a separate protocol: the budget is the mean observed development seconds/update pooled over all grid trials, multiplied by development updates. All arms exclude validation from this meter and record actual exposures. Equal counts/bytes/time are not interchangeable fairness criteria.
