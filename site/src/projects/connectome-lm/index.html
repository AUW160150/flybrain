Does fly wiring help a network predict text?

Take 512 real neurons and their 3,061 directed connections from the connectome. Make each connection a trainable weight, feed bytes of Shakespeare through learned embeddings, and train a readout. Compare against the same graph with its edges rewired while preserving every neuron's in- and out-degree. If the anatomy carries useful structure, the fly topology should win. It did not.

The result

On the sealed test split, averaging the three rewired controls for each seed and subtracting the fly model: mean −0.0103 bits per byte, 95% paired bootstrap interval [−0.0206, +0.0017]. Four of five seeds favoured rewiring. The interval includes zero, so no clear disadvantage is established either, and it falls well short of the predeclared +0.02 BPB practical advantage. This is one subgraph from one specimen, mostly visual neurons, with about 92% of those neurons' filtered connectivity falling outside the subset. It is a null result for this experiment, not a result about biological learning.

The design

  • Data. Tiny Shakespeare at a pinned revision, split contiguously 90/5/5 by bytes. An exact duplicate audit found no cross-split spans of 256 bytes or more. The test split was touched by nothing except hashing until the final command.
  • Graph. All 151,856,684 raw ordered pairs audited (no duplicates); 165,122 traced neurons and 6,235,649 directed pairs with ≥ 5 contacts retained; a 512-neuron neighbourhood sampled with seed 101. Exact body IDs and directions are preserved.
  • Model. UTF-8 bytes → learned embedding → one trainable parameter per allowed directed edge in the recurrent core (dense execution, masked) → linear readout. Everything learns from scratch; the graph is only a sparsity pattern. Width 32, context 128.
  • Controls. Degree-preserving directed rewiring (61,220 accepted swaps per control, ≈17% edge overlap with the original), random graphs at the same density, a GRU within 5% of the parameter count, and a diagonal "no cross-node recurrence" ablation.
  • Protocol. Smoke (5 runs) → pilot (15 runs, 3 seeds) → development grid (30 runs, seeds 901/902, three learning rates, selected on pooled validation only) → frozen confirmation (35 runs, seeds 11–55, lr 0.003) → one explicit final-evaluate command. The analysis plan, code, corpus, graphs and configuration were hashed into a freeze file before the confirmation run.

What was checked

After every stage an audit script replayed the saved validation scores and matched them to the logs within 10⁻⁶ BPB, verified code, plan, corpus and graph hashes, confirmed exact labelled degree preservation in the controls, matched initial edge-slot weights between fly and null arms, checked that every run consumed its full budget, and confirmed that no test loader had been opened. The final audit re-derived the paired bootstrap independently. The unit suite is 31 passed, 2 skipped (no CUDA or MPS in the deterministic CPU configuration).

Reproduce

cd projects/connectome-lm
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.lock && .venv/bin/pip install --no-deps -e .
./fly-lm download --cache-dir ../../data/flat-connectome      # MaleCNS flat files, ~1.07 GB
./fly-lm prepare --nodes 512 --sampling-seeds 101
./fly-lm smoke                                               # 5 runs, minutes
./fly-lm run --config pilot                                  # 15 runs
./fly-lm tune --config pilot --output configs/development-selection.json
./fly-lm freeze --config confirmation --selection configs/development-selection.json --output configs/confirmation-frozen.json
./fly-lm run --config confirmation --freeze configs/confirmation-frozen.json   # 35 runs, ~4.5 h on a laptop CPU
./fly-lm final-evaluate --freeze configs/confirmation-frozen.json

The confirmation reports, final review, audits, per-run values and the figure source are in reports/confirmation-211428f1ca1f/. Checkpoints and prepared graphs are not in the repository.
